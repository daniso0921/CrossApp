## Лабораторна робота 7. Звіти через LINQ: фільтри, проєкції, групування, топ- , агрегати

### Реалізовані запити у `ReportService`
* **`LowStock`**: фільтрація видань за порогом залишку (`< 10`), сортування за кількістю та стабільний вторинний ключ за `Isbn` (`Where`, `OrderBy`, `ThenBy`, `Select`).
* **`TopByQuantity`**: отримання топ-$N$ видань за кількістю примірників у спадному порядку з детермінованим сортуванням (`OrderByDescending`, `ThenBy`, `Take`, `Select`).
* **`ByUnit`**: групування книжкового фонду за жанрами з підрахунком кількості позицій та сумарного обсягу (`GroupBy`, `Select`, `Count`, `Sum`, `OrderByDescending`).
* **`Totals`**: агрегатні показники каталогу (загальна кількість назв, сума примірників, середнє та максимум) з безпечною обробкою порожніх колекцій.

### Приклади запуску CLI підкоманд
* `dotnet run --project src/Cli -- report-top` — вивід топ-5 видань за кількістю примірників.
* `dotnet run --project src/Cli -- report-low` — вивід дефіцитних позицій.
* `dotnet run --project src/Cli -- report-groups` — розподіл фонду за жанрами.
* `dotnet run --project src/Cli -- report-sum` — підсумкові агреговані показники каталогу.
* `dotnet run --project src/Cli -- report-demo` — демонстрація відкладеного виконання LINQ.

### Демонстрація відкладеного виконання (Deferred Execution)
LINQ-запити (такі як `Where`) виконуються не в момент їх оголошення, а під час реального перебирання чи виклику термінальних операторів (`Count()`, `ToList()`). Додавання елементів до джерела між викликами `Count()` змінює кінцевий результат, тоді як виклик `ToList()` повністю матеріалізує дані у пам'ять (створює знімок), захищаючи їх від подальших змін у вихідній колекції.
